# Azure deployment: report

24–25 October 2026. Status of Match Intelligence on Microsoft Azure: what's built, what's been tested, what blocked the live deployment, and what it costs. To deploy it, follow [GUIDE.md](GUIDE.md).

## Summary

- **Built and tested offline.** Everything the deployment needs exists in [`deploy/azure`](.) and passes its tests: Terraform for the VM, Key Vault, Azure OpenAI, Azure Machine Learning, the budget and the GitHub identity; the VM's deploy script; the CI and deploy workflows; the shirt-number model's Azure ML job.
- **Not deployed.** The subscription was upgraded from the Free Trial to pay-as-you-go on 24 October. It can't create the planned VM yet:
  - the quota for its VM family (ESv5) is 0 in every region checked;
  - UK South doesn't offer any E4 size to this subscription;
  - Azure ML's planned cluster size (`F8s_v2`) isn't offered in any region checked.

  We decided not to work around this with a VM for now, and to take the documented setup as working. [GUIDE.md](GUIDE.md) gives the route that fits this subscription.
- **Nothing is running on Azure, and nothing is charged.** No resource group, Key Vault, budget or Terraform state was created. The only change to the subscription is that the 12 resource providers the deployment uses are now registered, which is free.
- **The shirt-number model is trained.** It was trained locally with the same `train.py` the Azure ML job runs. On fonts it never saw, it reads 80% of legible numbers and invents a number on 0.3% of shirts that show none.

## What's built

| Azure service | What it does | Where |
|---|---|---|
| Virtual Machines | The whole stack on one VM, under p4n4-emu's `nuc` profile (4 cores, 14 GB, like a club's match device), behind HTTPS (Caddy, Let's Encrypt) | `main.tf`, `cloud-init.yaml.tftpl`, `vm/` |
| Managed identities, Microsoft Entra ID | The VM reads Key Vault and calls Azure OpenAI with no key; GitHub Actions signs in with OIDC and may only run commands on that VM | `keyvault.tf`, `openai.tf`, `github.tf` |
| Key Vault (RBAC) | The ten secrets, generated by Terraform, read by the VM on every deploy | `keyvault.tf`, `vm/deploy.sh` |
| Azure OpenAI | `gpt-4.1-mini` (GlobalStandard, 100k tokens a minute) for the team of agents, with keys off | `openai.tf`, `ai/agent/team.py` |
| Azure Machine Learning | A workspace and a CPU cluster that scales to zero; a command job that trains the shirt-number model, logs to MLflow, and registers it | `ml.tf`, `ai/vision/shirts/` |
| Cost Management | A monthly budget on the resource group that emails at 50%, 80% and 100% spent, and on a forecast over budget | `budget.tf` |
| DevTest Labs | An optional nightly shutdown | `main.tf` |

## What blocked the deployment

**1. The Free Trial was disabled (23 October).** The first `terraform plan` failed with `ReadOnlyDisabledSubscription`, and nothing was created. After the upgrade on 24 October, Azure answered inconsistently for a few minutes: some queries returned *Enabled, PayAsYouGo*, others *Disabled, FreeTrial*. We waited for ten consistent answers before going on.

**2. Resource providers.** A new subscription has none registered. The 12 the deployment uses are now registered. Terraform registers only the ones it lists, and doesn't do so until the subscription is writable.

**3. VM quota and availability.** Azure doesn't show a subscription's quota until `Microsoft.Compute` is registered. These were the numbers once it was:

| | UK South | UK West | North Europe | West Europe | Sweden Central |
|---|---|---|---|---|---|
| ESv5 quota (planned `E4s_v5`) | 0 | 0 | 0 | 0 | 0 |
| `E4s_v5` offered to this subscription | no | yes | – | no | yes |
| FSv2 quota | 10 | 10 | 10 | 10 | 10 |
| `F8s_v2` offered (planned ML cluster) | no | no | – | – | no |
| A size offered **and** with Azure ML quota | none | – | – | – | none |
| `E4s_v5` price per hour | $0.296 | $0.305 | – | – | $0.268 |

In UK South, the only 4-vCPU, 32 GB size offered with quota is `E4ns_v6`. It costs $0.436 an hour and needs an NVMe disk controller, which the Terraform doesn't set yet. Sweden Central offers `E4s_v5` as planned, at the lowest price, once 4 vCPUs of ESv5 quota are granted.

Azure ML has a quota of its own. In this subscription it's for families neither region offers: FSv2, ESv3, DASv4 and others. So the cluster needs a second request, for example 8 vCPUs of DSv5 for `D8s_v5` ($0.408 an hour in Sweden Central).

**4. Azure OpenAI was not a blocker.** `gpt-4.1-mini` (2025-04-14) is available in UK South and Sweden Central, with 200k tokens a minute of GlobalStandard quota. The deployment asks for 100k.

| Disk (128 GB Premium SSD) and IP | $0.92 a day | about the same | about the same |
| Azure ML's container registry | $0.17 a day | $0.17 a day | $0.17 a day |
| Azure OpenAI, Key Vault, storage, logs | cents | cents | cents |
| **Two weeks** | **about $115** | **about $105** | **about $160** |
| **A month** | **about $250** | **about $230** | **about $350** |

A full Azure ML training run costs about $1: roughly 2½ hours on an 8-vCPU node, which then scales to zero. The budget defaults to 100 a month in the billing currency. With the VM always on, it emails at 50% about six days in.

## The shirt-number model

It was trained locally rather than on Azure ML. The run used the same `train.py` the Azure ML job runs, with the job's defaults: 16 epochs of 24,000 synthetic players, ImageNet-initialised ResNet-18, 2 h 21 min on 8 CPUs. These are the results at the reader's 80% confidence threshold, on 2,000 players per set:

| | Read | Misread | Unread | Invented |
|---|---|---|---|---|
| Fonts it trained on | 91.3% | 0.4% | 8.3% | 0.8% |
| **Two fonts it never saw** | **79.9%** | **2.9%** | 17.2% | **0.3%** |
| An earlier short run (5 epochs × 8,000), new fonts | 61.0% | 3.1% | – | 0.9% |

A further 1,000 new players in the held-out fonts gave 448 of 551 legible numbers read, 17 misread and 2 inventions out of 449 shirts that showed none. Inference took 6.4 ms per crop on CPU through ONNX Runtime. The model is at `ai/vision/models/shirt_numbers.onnx`, which is git-ignored.

These are synthetic players only. The test that decides whether it replaces the vision-language model is real footage: our own kickabout with numbered bibs, compared with `matchvision.numbers_eval`. That footage hasn't been filmed yet.

## Recommendations

1. **To deploy, use Sweden Central with `E4s_v5`**, after two quota requests, both free and usually approved within minutes: 4 vCPUs of ESv5 for the VM, and 8 vCPUs of DSv5 for Azure ML's `D8s_v5` cluster. Set `location`, `size` and `ml_cluster_size`. [GUIDE.md](GUIDE.md), steps 3 and 4.
2. **Stay in UK South only with `E4ns_v6`.** That needs `disk_controller_type = "NVMe"` on the VM, which hasn't been written or tested, and costs about 47% more.
3. **Change the defaults** `size` and `ml_cluster_size` once one route has been deployed. They fail on a new subscription as they are.
4. **Before the video:** run the Azure ML job once, for the Studio metrics and the registered model, and film the kickabout for the real-footage test.
5. **After judging:** `terraform destroy`. Key Vault and Azure OpenAI are purged, so the same names can be used again.
