# Match Intelligence on Azure

The whole stack on one Azure VM, as the club's match device would run it, behind HTTPS, for anyone to open. From Terraform, in one `apply`:

| Azure | What it does here |
|---|---|
| **Virtual Machine** (`Standard_E4s_v5`, Ubuntu 24.04) | Runs the iot, ai and extras stacks under [p4n4-emu](https://github.com/raisga/p4n4-emu)'s `nuc` profile: the containers get a NUC's 4 cores and 14 GB, what a club's device would have, not the VM's 32 GB. Then Caddy (HTTPS, Let's Encrypt), p4n4-dashboard in the Premier League theme, and p4n4-api |
| **Public IP** with a DNS name | `<name>-<suffix>.uksouth.cloudapp.azure.com`; the NSG lets in 80, 443 and 8443 only (SSH from your address) |
| **Managed identity** (the VM's) | Reads Key Vault and calls Azure OpenAI: no key or password in the repository, the VM's image or its metadata |
| **Key Vault** (RBAC) | The ten secrets, generated by Terraform: the staff token, the device's, n8n's, InfluxDB's, Grafana's, the judges' login. The VM reads them on every deploy (`vm/deploy.sh`) |
| **Azure OpenAI** (`gpt-4.1-mini`, GlobalStandard) | The team of agents' model (`ai/agent/team.py`). Keys are off (`openai_keys`, for your own machine, turns them on): the VM signs in with Microsoft Entra ID, with the *Cognitive Services OpenAI User* role only |
| **Azure Machine Learning** (a workspace, a CPU cluster that scales to zero) | Trains the shirt-number model (`ai/vision/shirts/`) |
| **DevTest Labs schedule** (optional) | Stops the VM every night (`shutdown_time`) |
| **User-assigned identity** with a GitHub federated credential (optional) | The deploy workflow signs in with OIDC (no secret in GitHub) and may only run commands on this VM |

```
browser ──https──► Caddy :443  ──► p4n4-dashboard (PL theme) ──► p4n4-api ──► the feed, the agent, InfluxDB
                         │                        └─/grafana/──► Grafana (anonymous viewer)
                         └ :8443 ─► /analysis/, /api/v1/ ──► ingest (the analysis room; the staff token)
                                    /mail/ ──► Mailpit (the judges' login)  ·  /cameras/ ──► go2rtc's two streams
agent (team.py) ──Entra ID (managed identity)──► Azure OpenAI          deploy.sh ──managed identity──► Key Vault
```

## Before you start

- An Azure subscription (pay-as-you-go; the free credits cover two weeks), and the Azure CLI signed in: `az login`.
- Terraform ≥ 1.10, and an SSH key (`~/.ssh/id_ed25519.pub`, or `ssh_public_key_path`).
- **Quotas** in the region (Portal → Quotas): 4 vCPUs of *Standard ESv5 Family* for the VM, and for Azure ML 8 cores of *Standard FSv2 Family* (Azure ML has its own quota page). A new subscription often has 10 cores a family.
- The repository public on GitHub, for the VM to clone (`repo_url`). Until then, `vm/push.sh` copies your working tree instead.

## Deploy

```bash
cd deploy/azure
cp example.tfvars terraform.tfvars            # your subscription id; repo_url, github_repo
terraform init
terraform apply                               # about 10 minutes; the VM then deploys itself for about 20
terraform output -raw progress | sh           # follow the first deploy (Docker, images, the dashboard's build, Ollama's model)
# without repo_url, once the VM is up:  vm/push.sh
terraform output urls
terraform output -json judge_login            # the judges' logins
```

The first deploy builds the dashboard's image (Flutter, about 10 minutes) and pulls Ollama's model (4.6 GB, the offline fallback). The address answers once the deploy reaches the front, its last step: Caddy then gets its certificate in a few seconds.

| Open | Login |
|---|---|
| `https://<fqdn>/` | The dashboard, as user `judge` (the analyst's view: Home, the feed, Video, Grafana, the Assistant) |
| `https://<fqdn>:8443/analysis/` | The analysis room: any name, and the staff token (`analysis_token`) |
| `https://<fqdn>:8443/mail/` | The inbox: the staff's emails, the reports with the narrator's story (`judge`, the same password) |

**Again, after a change:** push to main, and the [deploy workflow](../../.github/workflows/deploy.yml) runs `bh-deploy` on the VM once CI has passed. Without the workflow: `terraform output -raw redeploy | sh` (Azure's run command, no SSH), `ssh p4n4@<ip> bh-deploy`, or `vm/push.sh` for the working tree. `bh-deploy` pulls the branch and runs [`vm/deploy.sh`](vm/deploy.sh), which is idempotent: secrets, `.env` files, the public links, `p4n4-emu up --profile nuc --build`, the dashboard's image, the front.

**The deploy workflow:** set `github_repo` and apply, then add `terraform output github`'s values as the repository's *variables* (Settings → Secrets and variables → Actions → Variables). Nothing secret: the workflow signs in with GitHub's OIDC token, which only `main` of that repository gets.

**On your own machine,** against the same deployment: apply with `openai_keys = true`, then `terraform output openai` and `az cognitiveservices account keys list -g <resource group> -n <account> --query key1 -o tsv` into `ai/.env`. The agent's container has no Azure CLI to sign in with, so it needs the key; the VM never does.

## Cost

Roughly, at pay-as-you-go prices in UK South (check the [pricing calculator](https://azure.microsoft.com/pricing/calculator/)):

| | |
|---|---|
| The VM, running | about $0.30 an hour (about $210 a month); stopped (deallocated), nothing |
| Its disk (128 GB Premium SSD), the IP | about $25 a month, running or not |
| Azure OpenAI | per token: a recap or an answer is well under a cent |
| Azure ML | the cluster only while a job runs (an `F8s_v2` is about $0.40 an hour; a training run takes about 2 hours); the workspace's storage and logs, pennies |
| Key Vault | pennies |

`shutdown_time = "2300"` stops the VM every night (start it again from the portal or `az vm start`); don't set it while it's being judged. `terraform destroy` removes everything (Key Vault and Azure OpenAI are purged, so the names can be used again).

## Security

- The VM answers on 80 (the redirect and Let's Encrypt), 443 and 8443. The agent (11434), n8n, InfluxDB, MQTT, Grafana's and go2rtc's own ports are published on the VM but closed by the NSG. go2rtc is reachable only for its two streams (its API can change its config).
- Secrets live in Key Vault and in Terraform's state (keep `terraform.tfstate` out of git and off shared disks; `.gitignore` has it), and on the VM in the layers' `.env` files (mode 600). Not in cloud-init's custom data, which the VM's metadata service serves to any process.
- The judges' account is an operator: they can make the analyst's calls and edit plans, not manage users or stacks. The analysis room's staff token can too: everything is synthetic, and `iot/scripts/reset_demo.sh` puts it back.
- The data is synthetic (`"synthetic": true` everywhere): no real match, player or footage is on the VM.

## Tests

```bash
terraform init -backend=false && terraform test     # mock providers: no Azure needed
```

They check the VM (size, image, disk), the address, that the NSG opens only SSH from your address and the web ports, that cloud-init says where the VM is and holds no secret, the Key Vault with RBAC and its ten secrets, the VM identity's two roles, Azure OpenAI without keys, the Azure ML cluster that scales to zero, and the options (no ML, the GitHub identity on main only, the nightly shutdown, a DNS label, the repository URL). CI runs them with `fmt` and `validate`.
